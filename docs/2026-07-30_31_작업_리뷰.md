## 5. 아키텍처 리뷰

### 잘 잡힌 점

1. **반복 가능한 PLP 골격**  
   데이터(lib) / UI(listing) / 라우트(page) 분리가 전 카테고리에 동일하게 적용되어, 세부·컬렉션·할인 확장이 일관됐다.

2. **시안·문서 우선**  
   “시안 없는 페이지는 진행하지 말 것” 원칙을 지키며 Figma 노드·데모 MD를 근거로 작업했다.

3. **GNB ↔ PLP 연결**  
   대분류·컬렉션 경로가 헤더/GNB와 맞춰져 탐색 흐름이 끊기지 않는다.

4. **할인 필터를 URL로 승격**  
   토글만 두지 않고 `/earlybird`, `/event` 라우트로 분리해 공유·새로고침·뒤로가기와 맞다.  
   커밋·원격 반영까지 끝나 배포 기준선과 로컬이 일치한다.

### 개선이 필요한 점

1. **데이터·에셋 중복**  
   베스트/새로운/시그니쳐는 기존 강의 에셋을 복제(ID만 prefix). 장기적으로는 단일 코스 소스를 두고 컬렉션이 참조하는 편이 유지보수에 유리하다.

2. **제목 문자열 매칭 취약**  
   데모 MD ↔ lib 강의명 부분 일치로 별점·할인 플래그를 맞춤. 표기 차이로 누락이 있어 수동 보정했다. ID 기반 매핑 테이블이 더 안전하다.

3. **1페이지짜리 카테고리 페이저**  
   `TOTAL_PAGES === 1`인 카테고리도 1·2 페이지 UI가 남는 경우가 있음. 페이지 수에 따라 페이저를 숨기거나 비활성화하는 편이 낫다.

4. **컬렉션 세부 칩 vs 할인 페이지**  
   베스트 등 컬렉션의 대분류 칩은 라우트가 없어, 할인 전용 페이지에서 칩을 누르면 `lockedDeal`과 클라이언트 `sub` 상태가 어긋날 수 있다. 대분류도 쿼리/라우트로 통일하거나, 할인 페이지에서는 칩을 전체로만 되돌리도록 명시하는 것이 좋다.

5. **커밋 단위가 매우 잘게 쪼개짐**  
   세부 카테고리마다 커밋이 많아 히스토리 추적은 쉽지만, “대분류 단위 1커밋”이 리뷰·리버트에는 더 편할 수 있다. (할인 기능은 `007977a`로 잘 묶였음)

6. **a11y**  
   할인 칩이 `Link` + `aria-pressed` 조합이라 버튼 토글 의미와 다소 어긋난다. `button`+`router.push` 또는 `aria-current` 검토 여지.
